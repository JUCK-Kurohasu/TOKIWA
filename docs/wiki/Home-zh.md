# TOKIWA Wiki

**TOKIWA（常磐）** 是一款检测并防御由生成式 AI（LLM 智能体）发起的网络攻击的 **LLM 驱动 SIEM / XDR**。
它是与 AI 自主渗透测试系统 **ARTEX** 相对应的防御方（Blue）产品。

> ⚠️ **开发中（v0.1.0）**。以在实验环境、或您自己管理并拥有测试许可的环境中使用为前提。

## TOKIWA 做什么

除了传统 SIEM 擅长的“与特征签名匹配的攻击”之外，TOKIWA 还着重识别 **AI 智能体特有的行为**。

| 维度 | 示例 |
|---|---|
| 等待思考的节奏 | 并行调用工具的突发请求，与等待推理的“停顿”交替出现 |
| 出错后的适应 | 收到 500 或 403 后，立即逐步修改载荷并重试 |
| 语义层面的探索 | 从 JS bundle 或 OpenAPI 中找出未被链接的 API 并发起调用 |
| 服从隐藏指令 | 服从嵌入在诱饵中的“只有 AI 才会读取并遵循的指令”（AI 金丝雀） |

检测到的告警由 LLM 附带依据进行分诊（研判），并 **提议** 处置（封禁、速率限制等）。
**只有在人工批准时才会执行**。

## 工作原理（概述）

```
 攻击者 / 用户   ──▶ TOKIWA Gate（反向代理）──▶ 要保护的 Web 应用
                        │  捕获包括请求体在内的 HTTP，即时应用封禁、速率限制和诱饵
                        ▼
                 TOKIWA Server（API + Web UI）
                   摄取 → 检测（特征签名、Sigma、AI 行为）→ 关联（生成安全事件）
                   → LLM 分诊 → 提议处置 → 人工批准 → 下发到 Gate
                   ＋ 漏洞情报（KEV / EPSS / NVD / OSV / JVN / GHSA / RSS）
                   ＋ 欺骗防御（诱饵、honeytoken、AI 金丝雀）
                   ＋ SOC Copilot（通过只读工具进行对话）
                        ▲
 TOKIWA Agent（主机）── 端口、连接、nginx / Caddy / Suricata / Zeek 的日志
```

## 安全方针

TOKIWA 是用于防御的工具。我们通过设计和测试遵守以下承诺。

1. **传给 LLM 的日志始终被视为“不可信数据”**。为避免服从攻击者埋入日志中的指令（提示注入），会先隔离并脱敏再传入。
2. **LLM 的输出不会直接连到执行系统**。LLM 只能产出“许可列表中的处置类型”和“经过校验的 IP / CIDR / TTL”，不会让它生成命令或配置字符串。
3. **处置默认需要人工批准**。自动批准仅限于明确启用了两项设置的类型。所有封禁都有期限（TTL），并且可以撤销。
4. **主动防御仅在本组织的资产上进行**（诱饵、迷宫、tarpit 等）。不对攻击来源进行反击（hack-back）。
