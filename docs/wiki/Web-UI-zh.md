# Web UI 指南

TOKIWA 的界面通过 `http://<服务器>:8788` 打开。左侧边栏分为 5 个分组。
可以通过右上角的按钮切换 **显示语言（日本語 / English）** 和 **浅色 / 深色主题**。
告警和安全事件会实时更新（SSE）。

Web UI 只提供日语和英语界面。本页用加粗的英文界面标签指代各项，并在首次出现时用括号附上中文译名。

## 角色（权限）

| 角色 | 可执行的操作 |
|---|---|
| `viewer` | 仅查看 |
| `analyst` | 在查看之外，还可执行分诊（研判）、更新安全事件、**批准、拒绝、撤销处置**、编辑欺骗防御资产等 |
| `admin` | 全部操作。管理用户、API 令牌、通知渠道、LLM 设置 |

最初在初始设置页面创建的用户是 `admin`。添加用户请在 **Settings → Users**（设置 → 用户）中进行。

## Monitor（监控）

### Dashboard（仪表盘）

过去 24 小时的整体概况。来源于 AI 智能体的信号以 **紫色** 显示。

- 上方的卡片：**Alerts (24h)**（告警数，按严重级别）、**Open incidents**（未关闭的安全事件）、
  **AI agent sessions (24h)**（AI 智能体会话数）、**LLM cost (today)**（今日 LLM 费用与预算）、
  **Pending actions**（待批准的处置）、**KEV matches**（已知被利用漏洞（KEV）与资产的匹配数）
- 活动：事件与告警的趋势（6 小时～7 天）
- 实时动态：打开页面之后新到达的告警、安全事件、处置提议
- 排名靠前的来源、排名靠前的规则、最近的安全事件

### Alerts（告警）

各个检测结果的列表。可以按状态、严重级别、类别、来源 IP、AI 评分筛选。
在详情页面中，可以查看作为依据的事件（证据）和 LLM 的分诊结果，并可以手动重新执行分诊。

### AI sessions（AI 会话）

按 **来源 + 客户端指纹** 汇总的行为单位（会话）。根据行为特征推定为
“AI 智能体 / 自动扫描器 / 人类 / 正常”，并给出 AI 评分。

- 列表：AI 评分、分类、请求数、错误率、路径数、持续时间
- 详情：请求时间线。与上一个请求的间隔（ms）会按“突发 / 中间 / 等待思考 / 长”的区间
  着色，可以看出 AI 智能体特有的 **突发 → 停顿 → 突发** 节奏。还会显示评分明细（哪些特征起了作用）。

### Hosts（主机）

TOKIWA Agent 发送过来的主机信息。标签页：**Ports**（端口：监听列表）和 **Baselines**（基线：许可列表）。
不在基线中的监听会被检测为“偏离”。

## Investigate（调查）

### Copilot（AI 助手）

可以用自然语言就 TOKIWA 的数据提问的聊天功能（例如：“今天被判定为 AI 智能体的来源有哪些？”）。
**Copilot** 可使用的工具是 **只读** 的，无法修改设置或执行处置。未设置 LLM 时，
返回的是模拟应答。

### Incidents（安全事件）

将相关告警按来源、会话、实体归并而成。

- 列表：严重级别、状态、**Actor attribution**（行为者判定：AI 智能体 / 人类 / 扫描器等）、AI 评分
- 详情：攻击阶段（杀伤链：侦察 → 初始入侵 → …）、LLM 的分诊（摘要、依据、推荐处置）、
  LLM 列出的“AI 参与的依据”、相关告警。可以分配 **Assignee**（负责人）并更新 **Status**（状态）。

对于 LLM 分诊中包含的依据（证据 ID），服务器会验证其是否对应真实存在的事件。

### Events（事件）

检索已摄取的原始事件。可以按类型、数据集、来源 IP、主机、时间范围、关键字（路径 / User-Agent）筛选。

## Intelligence（情报）

### Intelligence

漏洞信息以及与资产的比对结果。标签页：**Vulnerabilities**（漏洞：整合 KEV / EPSS / NVD / JVN / OSV / GHSA）、
**Asset matches**（资产匹配）、**Advisories**（安全通告：由 LLM 给出的带优先级的建议）、**News**（新闻：RSS）、**Web research**
（Web 调研：由 LLM 进行的 0day 调查）、**Sources**（数据源状态）。详情请参阅 [漏洞情报](Threat-Intel-zh)。

### Assets（资产）

登记需要保护的主机，以及在其上运行的软件（产品名、版本、CPE）。登记的资产会用于与漏洞信息的
比对，以及安全事件的优先级排序（是否命中 KEV）。

### Rules（检测规则）

- **Detectors**（检测器）：启用 / 禁用内置检测器（Web 攻击特征签名、AI 行为、欺骗防御、端口等）
- **Sigma rules**（Sigma 规则）：管理 Sigma 格式的规则（内置 25 条 + 追加的规则）
- **LLM proposals**（LLM 提议）：LLM 根据漏洞信息提议的规则。**不会自动启用**，需经审查后再采用

## Respond（处置）

### Response（处置）

由 LLM、规则、用户提议的处置列表。标签页：**Awaiting approval**（待批准）/ **Active**（生效中）/ **History**（历史）。
批准、拒绝、撤销需要 `analyst` 及以上角色。详情请参阅 [处置（审批流程）](Response-zh)。

### Deception（欺骗防御）

管理诱饵、honeytoken、AI 金丝雀、迷宫，以及查看触碰它们的记录（trip）。
也可以预览下发的内容。详情请参阅 [欺骗防御（Mirage）](Deception-zh)。

## System（系统）

### LLM

- **Settings**（设置）：提供商、模型（轻量 / 高级；Anthropic 下为下拉选择）、每日预算、输出语言、API 密钥（只写）。带有 **Connection test**（连接测试）按钮
- **Usage**（用量）：按日统计的费用、调用次数、token 数（按用途）
- **Call log**（调用记录）：所有 LLM 调用的审计日志。管理员还可以查看已脱敏的输入和应答正文

详情请参阅 [LLM 设置与成本](LLM-zh)。

### Settings（设置，仅限管理员）

**Users**（用户）、**API tokens**（API 令牌：传感器用，仅在创建时显示一次）、**Notifications**（通知渠道：Webhook / Slack / Discord / 电子邮件）、
**System**（系统：版本、环境、数据库、LLM 提供商状态、检测器、后台作业列表及手动执行）。
