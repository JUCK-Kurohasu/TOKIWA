# TOKIWA Wiki

**TOKIWA（常磐）** は、生成 AI（LLM エージェント）によるサイバー攻撃を検知・防御する **LLM 駆動 SIEM / XDR** です。
AI 自律型ペネトレーションテストシステム **ARTEX** と対をなす防御側（Blue）のプロダクトとして作られています。

> ⚠️ **開発中（v0.1.0）**。ラボや、自分が管理・試験の許可を持つ環境での利用を前提としています。

## TOKIWA がやること

従来の SIEM が得意な「署名に一致する攻撃」に加えて、**AI エージェントらしい振る舞い** を見分けることに重点を置いています。

| 観点 | 例 |
|---|---|
| 思考待ちのリズム | ツールを並列に叩くバーストと、推論待ちの「間」が交互に現れる |
| エラー後の適応 | 500 や 403 を受け取った直後に、ペイロードを少しずつ変えて再試行する |
| 意味的な探索 | JS バンドルや OpenAPI からリンクされていない API を見つけて叩く |
| 隠し指示への追従 | デコイに埋め込んだ「AI だけが読んで従う指示」（AI カナリア）に従う |

検知したアラートは LLM が根拠付きでトリアージし、対処（遮断・レート制限など）を **提案** します。
**実行するのは人間が承認したときだけ** です。

## しくみ（概要）

```
 攻撃者 / 利用者 ──▶ TOKIWA Gate（リバースプロキシ）──▶ 守りたい Web アプリ
                        │  HTTP をボディまで捕捉し、遮断・レート制限・デコイを即時適用
                        ▼
                 TOKIWA Server（API + Web UI）
                   取り込み → 検知（署名・Sigma・AI 振る舞い）→ 相関（インシデント化）
                   → LLM トリアージ → 対処の提案 → 人間が承認 → Gate に反映
                   ＋ 脆弱性インテリジェンス（KEV / EPSS / NVD / OSV / JVN / GHSA / RSS）
                   ＋ デセプション（デコイ・ハニートークン・AI カナリア）
                   ＋ SOC コパイロット（参照専用ツールでの対話）
                        ▲
 TOKIWA Agent（ホスト）── ポート・接続・nginx / Caddy / Suricata / Zeek のログ
```

## 安全方針

TOKIWA は防御のための道具です。次の約束を設計とテストで守っています。

1. **LLM に渡すログは常に「信頼できないデータ」として扱います**。攻撃者がログに仕込んだ指示（プロンプトインジェクション）に従わないよう、隔離・マスキングしてから渡します。
2. **LLM の出力を実行系に直結しません**。LLM が作れるのは「許可リストにある対処の種類」と「検証済みの IP / CIDR / TTL」だけで、コマンドや設定の文字列は作らせません。
3. **対処は人間の承認が既定です**。自動承認は、2 つの設定を明示的に有効にした種類だけに限られます。すべての遮断は期限付き（TTL）で、取り消せます。
4. **能動的防御は自組織の資産上だけ**（デコイ・迷路・tarpit など）。攻撃元への反撃（hack-back）は行いません。

| 項目 | 状態 |
|---|---|
| バックエンドの自動テスト（約 1,280 件）・フロントエンドのビルド・Docker イメージのビルドとスモークテスト | ✅ CI で常時実行 |
| ローカルでの一気通貫（攻撃シミュレータ → Gate → 検知 → インシデント → 承認 → Gate が 403 → 取り消し） | ✅ 確認済み（モック LLM） |

| `lab/compose.yaml` による Docker ラボの起動 | ⏳ 未確認 |
