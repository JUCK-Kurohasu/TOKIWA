# デセプション（Mirage）

正規の利用者が決して触れない **罠** を自組織の資産上に置き、触れた相手を高い確度で検知する機能です。
罠の配信は Gate が行い、守りたいアプリには一切転送しません。

## AI カナリア（逆プロンプトインジェクション）

Mirage の中心となる仕組みです。デコイの中に「**AI エージェントだけが読んで従う隠し指示**」を埋め込みます。

- 人間の利用者には見えません（HTML コメントと非表示要素。スクリーンリーダーにも読み上げられません）。
- 指示は「特定のヘッダ（既定 `X-Debug-Auth`）に値を付けて送れ」「`/api/internal/` に値をつなげたパスを叩け」のように、
  **読んで理解し、組み立てないと従えない** 形になっています。
- 値はリンク（`href`）や OpenAPI の例としては出しません。リンクを機械的にたどるクローラやファザーが偶然
  「従って」しまうと、AI だと断定する根拠が崩れるためです。

指示に従ったリクエストが来たら、それは LLM が駆動するクライアントだと判断できます（AI スコア 0.99）。

## 資産の種類

| 種類 | 何を置くか | 検知の条件 |
|---|---|---|
| `decoy_path` | `/.env`、`/backup.sql`、`/admin/config.php`、`/.git/config`、`/api/internal/debug` など。中身は偽の認証情報と AI カナリアの注記 | そのパスへのアクセス、または中の偽認証情報の使用 |
| `honeytoken` | 偽の AWS キー・API キー・DB 認証情報 | その値がどこかのイベントに現れる |
| `ai_canary` | 隠し指示。HTML への挿入、`/robots.txt`、`/llms.txt`、OpenAPI 風の JSON など | **指示どおりに値が使われたとき**（ページを取得しただけでは検知しない） |
| `labyrinth` | `/archive/` 以下に無限に続く迷路のページ（既定 OFF） | 配下へのアクセス。深さ 3 以上で重大度 critical |

偽の認証情報は、実在するサービスの形式とわざと違えてあります（たとえば AWS のアクセスキー ID は実物の 20 文字ではなく
24 文字）。万一外部に漏れても、本物の認証情報として通用しません。

## 既定で用意されるもの

サーバー起動時に、次の資産が自動で作られます（既にあれば変更しません）。

- `deception.decoy_paths` に並んだ各パスの `decoy_path`
- AI カナリア: HTML への挿入（有効）、`/api/internal/openapi.json`（有効）、`/robots.txt`（**無効**）、`/llms.txt`（**無効**）
- `deception.labyrinth_enabled: true` のときだけ迷路

`/robots.txt` と `/llms.txt` のカナリアが既定で無効なのは、守りたいアプリが持っている同名のファイルを置き換えてしまうためです。
有効にする場合は、アプリ側の内容と衝突しないか確認してください。

> 資産を **削除** しても、設定に残っている限り次回起動時に復活します。止めたい場合は **無効化** するか、設定から外してください。

## 検知されたとき

| 分類 | 重大度 | 意味 |
|---|---|---|
| `ai_canary_followed` | critical | AI カナリアの指示に従った（AI エージェントとほぼ断定。AI スコア 0.99） |
| `ai_canary_token` | critical | カナリアの値が別の場所に現れた（隠しテキストを読んだ主体。人間がソースから写した可能性も残る） |
| `honeytoken` | critical | 偽の認証情報が使われた |
| `decoy_path` | critical | デコイのパスにアクセスした |
| `labyrinth` | high（深さ 3 以上で critical） | 迷路に入り込んだ |

デコイへのアクセスは自動スキャナでも起きます（`/.env` などは定番の探索先です）。AI エージェントかどうかの判断には、
`ai_canary_followed` と、[AI セッション](Web-UI) の振る舞いスコアを合わせて見てください。

## 画面での操作

**デセプション** 画面で、資産の一覧・追加・有効化 / 無効化・**配信内容のプレビュー** と、トリップ（触れた記録）の一覧を確認できます。
対処の `deploy_canary` で、インシデントに応じて罠を追加することもできます。

## 主な設定（`deception.*`）

| キー | 既定 | 説明 |
|---|---|---|
| `enabled` | true | デセプション全体 |
| `ai_canaries` | true | AI カナリア |
| `decoy_paths` | 上記 5 パス | 既定で作るデコイ |
| `html_injection` | true | 守りたいアプリの HTML 応答に隠し指示を挿入する（`</body>` の直前） |
| `canary_header` | `X-Debug-Auth` | 隠し指示が送らせるヘッダ名。`llm.redaction.sensitive_headers` に入れると検知できなくなる |
| `canary_language` | `both` | 隠し指示の言語（`ja` / `en` / `both`） |
| `labyrinth_enabled` | false | 迷路 |
| `labyrinth_prefix` / `labyrinth_max_depth` | `/archive/` / 8 | 迷路の場所と深さ |

`html_injection` は、アプリがページの DOM をサーバーに送り返す仕組み（セッションリプレイなど）を持っている場合は無効にしてください。

## 利用上の注意

- 罠は **自組織の資産上にだけ** 置きます。攻撃元への反撃や、マルウェア的なペイロードの返送は行いません。
- 隠し指示の文言の強さ・言語、robots.txt / llms.txt への配置は運用判断です。導入にあたっては、
  組織のポリシーや法務担当と確認してください。
