# Web UI ガイド

TOKIWA の画面は `http://<サーバー>:8788` で開きます。左のサイドバーは 5 つのグループに分かれています。
右上のボタンで **表示言語（日本語 / English）** と **ライト / ダークテーマ** を切り替えられます。
アラートやインシデントはリアルタイムに更新されます（SSE）。

日時には常にタイムゾーン名が付きます（例: `2026/11/11 9:43:09 JST`）。右上の時計ボタン（`JST` / `UTC` などと表示）で
**表示タイムゾーン（ブラウザのローカル / UTC）** を切り替えられ、選択はブラウザごとに記憶されます。日時にマウスを乗せると
UTC の ISO 8601 形式（例: `2026-11-11T00:43:09.000Z`）も表示されます。API・生データ (JSON)・Gate やログの時刻は常に UTC です。
イベント画面の期間指定（カスタム）も、表示タイムゾーンで入力した時刻として扱います。

## ロール（権限）

| ロール | できること |
|---|---|
| `viewer` | 閲覧のみ。イベントのリクエストボディ・クエリ・ヘッダ値・コマンドライン・プロンプトは伏字（`[redacted: analyst role required]`）で表示。コパイロットは既定で使えない（`copilot.min_role`） |
| `analyst` | 閲覧に加えて、トリアージの実行、インシデントの更新、**対処の承認・却下・取り消し**、デセプション資産の編集など |
| `admin` | すべて。ユーザー・API トークン・通知チャネル・LLM 設定の管理 |

最初にセットアップ画面で作ったユーザーは `admin` です。ユーザーの追加は **設定 → ユーザー** で行います。

ログインの有効期間は既定で 12 時間です（`server.token_ttl_minutes`）。右上の **ログアウト** は、そのユーザーの **すべての端末** のログインを無効にします。パスワードやロールを変更したときも、そのユーザーの既存のログインは無効になり、ログインし直しが必要です。管理者は **設定 → ユーザー** の **セッション失効** で、他のユーザーをすべての端末からログアウトさせられます（ログイン情報が盗まれた疑いがあるとき）。

## 監視

### ダッシュボード

過去 24 時間の全体像です。AI エージェントに由来するシグナルは **紫** で表示されます。

- 上段のカード: アラート件数（重大度別）、オープンなインシデント、AI エージェントのセッション数、今日の LLM 費用と予算、
  **承認待ちの対処**、既知の悪用脆弱性（KEV）と資産の一致数
- アクティビティ: イベントとアラートの推移（6 時間〜7 日）
- ライブフィード: 画面を開いてから届いた新着のアラート・インシデント・対処提案
- 上位送信元・上位ルール・最近のインシデント

### アラート

個々の検知結果の一覧です。状態・重大度・カテゴリ・送信元 IP・AI スコアで絞り込めます。
詳細画面では、根拠となったイベント（証拠）と LLM のトリアージ結果を確認でき、トリアージを手動で再実行できます。

状態を **誤検知** にすると、再発の扱いを選ぶダイアログが開きます（一覧の一括変更でも同じ）。

| 選択肢 | 動き |
|---|---|
| サーバー既定（初期選択） | `detection.fp_suppress_hours`（既定 168 時間）だけ、同じ検知（同じルール・一致した署名・パス・送信元）の再発を新しいアラートにせず、このアラートの件数に加算する。トリアージ・通知・インシデントへの紐付けは起きない |
| 抑制しない | 再発は通常どおり新しいアラートになる |
| 指定した時間だけ抑制 / 恒久的に抑制 | 期間を変える（恒久は解除するまで） |
| 送信元を問わず抑制する | 同じルート・パラメータへの同種の検知が、どの送信元からでも黙る。攻撃者が同じ形で狙っても見逃すので、送信元が多数で毎回変わる正規の入力に限る |

新しい署名・別のパラメータ・重大度の上昇は抑制されません。誤検知にしたアラートの詳細には、そのアラートから作られた抑制
（期限・抑えた件数）と **解除** ボタンが表示されます。誤検知から別の状態に戻すと、抑制も解除されます（確認が出ます）。

### 抑制・許可リスト

誤検知にしたアラートの再発抑制と、許可済みの脆弱性診断・負荷試験の **許可リスト** の一覧です（種類で絞り込み、期限切れ・解除済みの表示切替）。
抑制中の検知は、新しいアラート・トリアージ・通知・対処提案になりません。**解除** は `analyst` 以上が行えます。

**許可リストを作成** は `admin` だけが使えます。送信元 CIDR と期間（時間）が必須で、ルール ID とパスは任意です。

- 期間の上限は `detection.allowlist_max_hours`（既定 720 時間）。恒久の許可リストは作れません。
- IPv4 で /8、IPv6 で /32 より広い範囲は作れません。
- 扱いは「info で記録する」（既定。アラート一覧には残るがトリアージ・通知・提案はしない）か「記録しない」（件数だけ数える）。
- ルールを絞らない許可リストは、デセプション（デコイ踏み）や AI エージェント判定のアラートも静かにします。範囲と期間は最小にしてください。

### AI セッション

**送信元 + クライアント指紋** ごとにまとめた行動の単位（セッション）です。振る舞いの特徴量から
「AI エージェント / 自動スキャナ / 人間 / 正常」を推定し、AI スコアを付けます。

- 一覧: AI スコア、分類、リクエスト数、エラー率、パス数、継続時間
- 詳細: リクエストのタイムライン。直前のリクエストからの間隔（ms）が「バースト / 中間 / 思考待ち / 長い」の帯で
  色分けされ、AI エージェント特有の **バースト → 間 → バースト** のリズムが見えます。スコアの内訳（どの特徴が効いたか）も表示されます。

### ホスト

TOKIWA Agent が送ってきたホストの情報です。タブ: **ポート**（待ち受けの一覧）と **ベースライン**（許可リスト）。
ベースラインにない待ち受けは「逸脱」として検知されます。

## 調査

### コパイロット

TOKIWA のデータについて自然言語で質問できるチャットです（例:「今日 AI エージェントと判定された送信元は？」）。
コパイロットが使えるツールは **参照専用** で、設定の変更や対処の実行はできません。LLM を設定していない場合は
モックの応答になります。

回答の中のリンクは、攻撃者がテレメトリに仕込んだ指示に LLM が従う可能性を考えて、次のように扱います。

- TOKIWA 内のリンクは既知の画面（アラート・インシデント・セッション・イベントなど）だけが同じタブで開きます。
- 外部リンクは許可したサイト（NVD・MITRE・CISA・JVN・OSV・FIRST）の https だけがクリックでき、表示名の横に実際のホスト名が出ます。
  それ以外はクリックできない文字列として、ホスト名と「リンク無効」を添えて表示します。
- 表示名が URL の形なのに実際のリンク先と違う場合は「表示とリンク先が異なります」と警告します。

許可するサイトは `frontend/src/components/common/linkPolicy.ts` の `EXTERNAL_LINK_ALLOWLIST` で変更できます（要ビルド）。

### インシデント

関連するアラートを、送信元・セッション・エンティティで束ねたものです。

- 一覧: 重大度、状態、**アクター判定**（AI エージェント / 人間 / スキャナなど）、AI スコア
  （アクター判定はルールと振る舞いで決めます。ルールで判定できないときだけ LLM の判定を使い、それも AI エージェント / スキャナへの
  引き上げに限ります。LLM が「人間」「無害」と判定しても変わりません）
- 詳細: 攻撃の段階（キルチェーン: 偵察 → 初期侵入 → …）、LLM のトリアージ（要約・根拠・推奨対処）、
  LLM が挙げた「AI 関与の根拠」、関連アラート。担当者の割り当てと状態の更新ができます。

LLM のトリアージに含まれる根拠（証拠 ID）は、実在するイベントかどうかをサーバーが検証しています。

### イベント

取り込んだ生イベントの検索です。種別・データセット・送信元 IP・ホスト・期間・キーワード（パス / User-Agent）で絞り込めます。

パス・User-Agent・ヘッダ・ボディなどに **見えない文字や表示順を入れ替える文字**（双方向制御文字 U+202E、ゼロ幅文字 U+200B など）が
含まれる場合、その文字を `⟨U+202E⟩` のように警告色で表示し、行やイベントに「不可視/双方向制御文字を含む」バッジを付けます
（攻撃者が `invoice⟨U+202E⟩fdp.exe` を `invoiceexe.pdf` に見せかける手口への対策）。生データ (JSON) では `\u202E` の形で表示します。
置き換えは表示だけで、検索・絞り込みには元の文字列が使われます。イベント一覧・イベント詳細・アラートの証拠・セッション詳細・
コパイロットの回答とツール結果に適用されます。

## インテリジェンス

### インテリジェンス

脆弱性情報と、資産との照合結果です。タブ: **脆弱性**（KEV / EPSS / NVD / JVN / OSV / GHSA の統合）、
**資産一致**、**アドバイザリ**（LLM による優先度付きの助言）、**ニュース**（RSS）、**Web リサーチ**
（LLM による 0day 調査）、**ソース状態**。詳しくは [脆弱性インテリジェンス](Threat-Intel)。

GHSA / OSV が取り下げた（誤報・重複などで撤回した）アドバイザリは、脆弱性一覧・詳細と資産一致に **取り下げ済み** バッジで示します
（脆弱性全体が取り下げられ、それに基づく露出は自動でクローズ済み）。一部のアドバイザリだけが取り下げられ、NVD など他の提供元のデータが
残っている場合は **一部取り下げ** です。バッジにマウスを乗せると、取り下げられたアドバイザリ ID と日時が出ます。バッジは脆弱性の状態を
示すもので、個々の露出が閉じた理由を断定するものではありません（自動クローズの理由欄は従来の文言のままです）。

### 資産

守るべきホストと、そこで動くソフトウェア（製品名・バージョン・CPE）を登録します。登録した資産が脆弱性情報との
照合や、インシデントの優先度付け（KEV に該当するか）に使われます。

### 検知ルール

- **検知器**: 組み込みの検知器（Web 攻撃の署名、AI 振る舞い、デセプション、ポートなど）の有効 / 無効
- **Sigma ルール**: Sigma 形式のルールの管理（同梱 25 本 + 追加分）。同梱の Web 攻撃ルール 14 本は、同じリクエストで同じ種類の
  組み込み Web 検知器が発報するとそちらに統合され（アラートは 1 件、`details.corroborated_by` に記録）、検知器が有効なのに
  発報しなかったときは low で記録されます。検知器を無効にしたときだけルール本来の重大度で出ます
- **LLM 提案**: 脆弱性情報から LLM が提案したルール。**自動では有効化されず**、レビューして採用します

## 対処

### 対処

LLM・ルール・ユーザーが提案した対処の一覧です。タブ: **承認待ち** / **有効** / **履歴** / **抑止**（却下・取り消しで「再提案しない」とした対象の一覧と解除）。
承認・却下・取り消しは `analyst` 以上が行えます。詳しくは [対処（承認ワークフロー）](Response)。

### デセプション

デコイ・ハニートークン・AI カナリア・迷路の管理と、それらに触れた記録（トリップ）です。
配信内容のプレビューもできます。詳しくは [デセプション（Mirage）](Deception)。

## システム

### LLM

- **設定**: プロバイダ、モデル（軽量 / 上位。Anthropic ではプルダウンで選択）、日次予算、出力言語、API キー（書き込み専用）。**接続テスト** ボタンあり
- **使用量**: 日別の費用・呼び出し回数・トークン数（用途別）
- **呼び出し履歴**: すべての LLM 呼び出しの監査ログ。管理者は、マスク済みの入力と応答の本文も確認できます

詳しくは [LLM の設定とコスト](LLM)。

### 設定（管理者のみ）

**ユーザー**、**API トークン**（センサー用。作成時に一度だけ表示）、**通知チャネル**（Webhook / Slack / Discord / メール）、
**システム**（バージョン・環境・DB・LLM プロバイダの状態、検知器、バックグラウンドジョブの一覧と手動実行）。
