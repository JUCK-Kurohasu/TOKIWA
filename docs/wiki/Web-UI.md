# Web UI ガイド

TOKIWA の画面は `http://<サーバー>:8788` で開きます。左のサイドバーは 5 つのグループに分かれています。
右上のボタンで **表示言語（日本語 / English）** と **ライト / ダークテーマ** を切り替えられます。
アラートやインシデントはリアルタイムに更新されます（SSE）。

## ロール（権限）

| ロール | できること |
|---|---|
| `viewer` | 閲覧のみ |
| `analyst` | 閲覧に加えて、トリアージの実行、インシデントの更新、**対処の承認・却下・取り消し**、デセプション資産の編集など |
| `admin` | すべて。ユーザー・API トークン・通知チャネル・LLM 設定の管理 |

最初にセットアップ画面で作ったユーザーは `admin` です。ユーザーの追加は **設定 → ユーザー** で行います。

## 監視

### ダッシュボード

過去 24 時間の全体像です。AI エージェントに由来するシグナルは **紫** で表示されます。

- 上段のカード: アラート件数（重大度別）、オープンなインシデント、AI エージェントのセッション数、今日の LLM 費用と予算、
  **承認待ちの対処**、既知の悪用脆弱性（KEV）と資産の一致数
- アクティビティ: イベントとアラートの推移（6 時間〜7 日）
- ライブフィード: 画面を開いてから届いた新着のアラート・インシデント・対処提案
- 上位送信元・上位ルール・最近のインシデント

### アラート

個々の検知結果の一覧です。状態・重大度・カテゴリ・送信元 IP・AI スコアで絞り込めます。
詳細画面では、根拠となったイベント（証拠）と LLM のトリアージ結果を確認でき、トリアージを手動で再実行できます。

### AI セッション

**送信元 + クライアント指紋** ごとにまとめた行動の単位（セッション）です。振る舞いの特徴量から
「AI エージェント / 自動スキャナ / 人間 / 正常」を推定し、AI スコアを付けます。

- 一覧: AI スコア、分類、リクエスト数、エラー率、パス数、継続時間
- 詳細: リクエストのタイムライン。直前のリクエストからの間隔（ms）が「バースト / 中間 / 思考待ち / 長い」の帯で
  色分けされ、AI エージェント特有の **バースト → 間 → バースト** のリズムが見えます。スコアの内訳（どの特徴が効いたか）も表示されます。

### ホスト

TOKIWA Agent が送ってきたホストの情報です。タブ: **ポート**（待ち受けの一覧）と **ベースライン**（許可リスト）。
ベースラインにない待ち受けは「逸脱」として検知されます。

## 調査

### コパイロット

TOKIWA のデータについて自然言語で質問できるチャットです（例:「今日 AI エージェントと判定された送信元は？」）。
コパイロットが使えるツールは **参照専用** で、設定の変更や対処の実行はできません。LLM を設定していない場合は
モックの応答になります。

### インシデント

関連するアラートを、送信元・セッション・エンティティで束ねたものです。

- 一覧: 重大度、状態、**アクター判定**（AI エージェント / 人間 / スキャナなど）、AI スコア
- 詳細: 攻撃の段階（キルチェーン: 偵察 → 初期侵入 → …）、LLM のトリアージ（要約・根拠・推奨対処）、
  LLM が挙げた「AI 関与の根拠」、関連アラート。担当者の割り当てと状態の更新ができます。

LLM のトリアージに含まれる根拠（証拠 ID）は、実在するイベントかどうかをサーバーが検証しています。

### イベント

取り込んだ生イベントの検索です。種別・データセット・送信元 IP・ホスト・期間・キーワード（パス / User-Agent）で絞り込めます。

## インテリジェンス

### インテリジェンス

脆弱性情報と、資産との照合結果です。タブ: **脆弱性**（KEV / EPSS / NVD / JVN / OSV / GHSA の統合）、
**資産一致**、**アドバイザリ**（LLM による優先度付きの助言）、**ニュース**（RSS）、**Web リサーチ**
（LLM による 0day 調査）、**ソース状態**。詳しくは [脆弱性インテリジェンス](Threat-Intel)。

### 資産

守るべきホストと、そこで動くソフトウェア（製品名・バージョン・CPE）を登録します。登録した資産が脆弱性情報との
照合や、インシデントの優先度付け（KEV に該当するか）に使われます。

### 検知ルール

- **検知器**: 組み込みの検知器（Web 攻撃の署名、AI 振る舞い、デセプション、ポートなど）の有効 / 無効
- **Sigma ルール**: Sigma 形式のルールの管理（同梱 25 本 + 追加分）
- **LLM 提案**: 脆弱性情報から LLM が提案したルール。**自動では有効化されず**、レビューして採用します

## 対処

### 対処

LLM・ルール・ユーザーが提案した対処の一覧です。タブ: **承認待ち** / **有効** / **履歴**。
承認・却下・取り消しは `analyst` 以上が行えます。詳しくは [対処（承認ワークフロー）](Response)。

### デセプション

デコイ・ハニートークン・AI カナリア・迷路の管理と、それらに触れた記録（トリップ）です。
配信内容のプレビューもできます。詳しくは [デセプション（Mirage）](Deception)。

## システム

### LLM

- **設定**: プロバイダ、モデル（軽量 / 上位）、日次予算、出力言語、API キー（書き込み専用）。**接続テスト** ボタンあり
- **使用量**: 日別の費用・呼び出し回数・トークン数（用途別）
- **呼び出し履歴**: すべての LLM 呼び出しの監査ログ。管理者は、マスク済みの入力と応答の本文も確認できます

詳しくは [LLM の設定とコスト](LLM)。

### 設定（管理者のみ）

**ユーザー**、**API トークン**（センサー用。作成時に一度だけ表示）、**通知チャネル**（Webhook / Slack / Discord / メール）、
**システム**（バージョン・環境・DB・LLM プロバイダの状態、検知器、バックグラウンドジョブの一覧と手動実行）。
