## 前提・仮定（統合時に確認）

- `deploy/Dockerfile` の ENTRYPOINT `docker-entrypoint` が `serve` / `sh ...` / `tokiwa ...` を通すこと、
  `TOKIWA_HEALTHCHECK_URL`（gate は `/__tokiwa/health`、他は `none`）を参照（devops ブランチで確認済み）。
- gate は `TOKIWA_GATE__*` 環境変数で設定でき `tokiwa gate run` で起動、`/__tokiwa/health` を持つ（gate 仕様どおり）。
- agent は `TOKIWA_AGENT__NGINX_JSON_LOGS` を読む。nginx ログ形式は sensors の `lab/nginx/tokiwa-json.conf`
  （`/var/log/nginx/tokiwa-access.json`）をそのまま conf.d にマウント（複製なし）。
- トークンは `tokiwa-data` ボリュームの `lab-tokens/`（イメージの非 root ユーザー所有, 600）。gate/agent/sim-ingest は
  同ボリュームを `/tokiwa-data:ro` で参照。init が先に `/data` でマウントしてボリュームの所有者を初期化する前提
  （depends_on で順序付け）。

## 他モジュールへの依頼

- deception: オフライン評価でカナリア検知を測るため、資産を登録する関数（例 `deception.service.seed_asset(kind, token, path)`）
  があればハーネスから呼べる。現状オフライン再生ではトークン一致検知は評価できない（デコイパス一致は可）。
  カナリア文言が確定したら `eval/discovery.py` の解析（`X-...: <token>` ヘッダ指示とパス）と合っているか確認してほしい。
- triage: トリアージ完了時に `alert.updated`（triage 付き）を publish してもらえると、alert→triage 遅延をバスで正確に測れる
  （無い場合は DB の updated_at で近似）。
- gate: ラボでは `TOKIWA_GATE__TRUST_FORWARDED_FOR=true`（シミュレータの `--spoof-xff` 用）。
