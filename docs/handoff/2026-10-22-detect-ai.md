## 他モジュールへの依頼
- **triage-correlate**: セッション単位で束ねるときは alert の `entities.session_id` を使えます（全 ai.*/llm_app.* が付与）。
  プロセス内からは `tokiwa.aidetect.sessions.current_tracker().get(session_id)` で最新の特徴量・indicators を DB を介さず
  参照できます。`actor_sessions.incident_id` は sessionizer の upsert では一切書き換えません（テストで保証）。
- **frontend-core**: `GET /sessions/{id}` の timeline に `method, kind, event_id, error, band` を追加しました（契約の上位互換）。
  `band` = burst/mid/think/long で色分けすると「思考待ちのリズム」が見えます。`session.features.indicators[]` は
  `{key, ja, en, signal, weight, contribution, direction, evidence}`、`features.scores = {ai, scanner, hostile}`。
  `frontend/src/api/types.ts` に SessionDetail 型の追加をお願いします（共有ファイルのため未編集）。
- **deception**: AI カナリア追従は `EventKind.DECEPTION` かつ `deception.asset_kind == "ai_canary"` のイベントで
  セッションに反映されます（ai_score を 0.99 に床上げ、分類 ai_agent）。Gate がデコイ応答をこの形で記録することを前提にしています。
- **lab-eval**: `backend/tests/aidetect/synth.py` は検知側の仮説をそのまま形にした合成データです。評価には独立に作られた
  シミュレータ/ARTEX のトラフィックを使ってください（同じ仮説で作ると評価が甘くなります）。
