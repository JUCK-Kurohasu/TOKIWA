## やったこと

### エージェント側（`tokiwa agent`、別プロセス）
- `sensors/host.py`: psutil で listener（tcp/udp, v4/v6, プロセス name/exe/cmdline/user）と新規
  ESTABLISHED/SYN_RECV 接続を収集（`asyncio.to_thread`）。root なしでも動く: 所有プロセスが見えない
  ソケットは `process=None`、取得拒否された項目は欠損扱い、スナップショットに `labels.process_info=partial`。
  macOS 等で `net_connections` が拒否されたらプロセス単位にフォールバック。列挙自体が失敗したサイクルは
  スナップショットを送らない（空スナップショット＝全ポート closed と誤認されるため）。cmdline は redact。
- `sensors/logtail.py`: `tail -F` 相当。inode 変化でローテーション検知（旧ファイルを読み切ってから新ファイルを
  先頭から）、サイズ縮小で copytruncate 検知、開始位置 end/beginning、行の途中は次回まで保持。
- アダプタ: `nginx.py`（`nginx.access`）、`caddy.py`（`caddy.access`）、`suricata.py`（`suricata.eve`:
  alert→IDS_ALERT, http→HTTP, flow→CONNECTION, dns→DNS）、`zeek.py`（conn/http/notice、TSV と JSON。
  末尾から tail 開始時は `read_head()` で `#fields` を取得）。ヘッダ・クエリ・パス・UA は `llm.redact`、
  raw は秘密キー（password/cookie/authorization…、Suricata の name/value ヘッダ配列も）をマスクして 4KB 上限。
- `sensors/shipper.py`: バッチ（既定 500、最大 5000）、指数バックオフ+ジッタ、オフライン時はバッファ保持
  （上限超過は古い順に破棄・計数）、失敗後はフラッシュ間隔も指数的に延ばす。400/413/422 は破棄、401/403 は保持。
- `sensors/agent.py` + `sensors/cli.py`: `tokiwa agent run`（AgentSettings + CLI 上書き、SIGINT/SIGTERM で
  フラッシュして終了）、`tokiwa agent once --print`（ログは先頭から読み JSON 配列を出力。`--print` なしは 1 回送信）。
- `lab/nginx/tokiwa-json.conf`: 推奨 `log_format tokiwa_json escape=json`（Cookie/Authorization は記録しない）。

### サーバー側
- `enrich/ports.py`（order 20）: PORT_SNAPSHOT を `host_ports` と比較し PORT_CHANGE
  （opened/closed/process_changed）を **同じバッチのスナップショット直後に挿入**。検知器は DB を見ないので、
  ベースライン照合結果を labels に載せる（`baseline`, `baseline.allow_public`, `baseline.process_mismatch`,
  `port.initial`, `port.previous_process`）。未知ホストの初回: 既定 `info`（initial 付きで出す）/ `learn`（出さない）。
  所有プロセスが見えなくなっただけ（非 root 再起動）は変化扱いせず最後の既知プロセスを保持。
- 検知器: `port.unexpected_listener`（全 IF=high / 特定 IP=medium / loopback=low / 初回=info）、
  `port.public_exposure`（allow_public=false の全 IF バインド）、`port.process_changed`（ベースラインの指定
  プロセスと不一致なら high）、`net.port_scan`（T1046、送信元ごとの窓で宛先ポート/ホスト数）、
  `net.ids_alert`（Suricata severity 1/2/3→high/medium/low、Zeek notice は prefix 表）。
- `schemas/hosts.py`（HostPort, PortBaseline, PortBaselineIn, HostSummary, BaselineLearnRequest, match_baseline）、
  `api/routes/hosts.py`（契約どおり + `?open`/`?host` フィルタ、変更系は監査ログ）。

## 既知の制限・設計判断
- `net.port_scan` は `network.direction == "outbound"` を数えない（自ホスト発の多数接続での誤検知回避）。
  侵害ホストからの外向きスキャンは未対応（別検知器が必要）。ホストセンサーは open ポートへの接続しか見えない。
- UDP の ephemeral 範囲の未接続ソケットは listener として報告しない（ノイズ回避。UDP バックドアの見逃しとの
  トレードオフ、設定で無効化可）。
- ports enricher は自前のトランザクションで host_ports を確定する（イベント保存失敗時は 1 スナップショット先行）。
  プロセス内 `asyncio.Lock` で直列化（複数ワーカー構成では要再検討）。
- Caddy のヘッダは Go map 由来で順序が無いため `header_order` は空。
- 初回スナップショットの unexpected_listener は info で出る（既定）。運用開始時は `POST /hosts/baselines/learn` 推奨。
