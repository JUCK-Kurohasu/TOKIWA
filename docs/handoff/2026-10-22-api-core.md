## 設計判断・ハマりどころ

- **httpx の ASGITransport はレスポンス全体をバッファする**ので無限 SSE を読めない。テストでは
  `tests/api/conftest.py::SSEConnection`（同じイベントループで ASGI アプリを直接駆動する最小クライアント）を使う。
- **SSE の認証で `DbSession` 依存を使わない**: 現行 FastAPI では yield 依存の後処理がレスポンス送信完了後に走るため、
  `CurrentUser` をそのまま使うと SSE 接続中ずっと DB 接続をプールから占有する（クライアント 15 本でプール枯渇）。
  `stream._stream_user` で短命セッションを開き `deps.get_current_user` をそのまま呼んで再利用している。
- **JWT がアクセスログに残る問題**: 契約上 SSE は `?access_token=<JWT>` を使うため、uvicorn のアクセスログに JWT が平文で出ていた
  （AGENTS.md §2-5 違反）。`stream.py` で `uvicorn.access` ロガーに `RedactAccessToken` フィルタを入れて `[REDACTED]` に置換
  （実 uvicorn で確認済み）。本来はアプリ/ロギング初期化側に置くべき → 統合担当へ依頼（下記）。
- SQLAlchemy 2.1 の `Select` は可変長ジェネリック（`Select[Any]` は 1 列の意味）なので、ヘルパは `Select[*Ts]` で型付け。
- タイムラインのバケットはエポック整列（ポーリングのたびに境界がずれない）。最後のバケットが現在時刻を含む。
- dashboard の定義（api-contract.md にも記載）: alerts_24h = last_seen 24h 以内 / open_incidents = resolved・false_positive 以外
  （contained は未クローズ扱い）/ ai_sessions・ai_alerts = ai_agent 分類または ai_score ≥ `detection.ai_agent_threshold` /
  llm_cost_today_usd = `get_gateway().spent_today_usd()`（予算判定と同じ直近 24h）/ top_* の count = アラートの count 合計。
- ステータスコード: POST /users・/tokens は 201、DELETE は 204（フロントの `request()` は空ボディを扱える）。

## 次の一手 / 未完

- 大量データ時の性能: `/events` の総件数は絞り込み後 `count(*)`、タイムラインは最大 7 日分の行を Python に流す
  （`yield_per=5000` でメモリは一定）。数百万件規模になったら方言別 SQL バケット集計かロールアップテーブルを検討。
- `event.ingested` はバッチごとに 1 メッセージ。高レート時は 1 秒単位の合算（コアレス）を検討。
- bus のリスナーキューは maxsize 1000。遅いクライアントでは欠落し、bus が欠落ごとに warning を出す。
