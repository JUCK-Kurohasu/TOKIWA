## 要判断

- #161: 監査の推奨 (a)(b) は「env=prod では起動失敗」。**既定は警告のみ**にし、拒否は `TOKIWA_STRICT_CONFIG=1` の opt-in にした
  （イメージは `TOKIWA_ENV=prod` を焼き込んでおり、`.env` に Compose 用の変数や将来のスクリプト用の変数があると全環境が起動しなくなるため）。
  本番で strict を既定にするかはユーザー判断（`OPERATIONAL_ENV_VARS` に漏れがあると起動不能になる点に注意）。
- #161: 推奨 (c) の「/api/v1/system に設定ソースのハッシュ」は未実施（`api/routes/system` は api レーンの所有。必要なら `config_diagnostics.config_file_status()` を返す）。

## 既定動作の変更

- #161: 起動時に `config:` で始まる WARNING が出るようになった（未知キー・未知の `TOKIWA_*`・見つからない設定ファイル）。動作は変えない。
- #161: `TOKIWA_CONFIG=`（空）は以前も実質「読まない」だったが、明示的な意味として文書化。
- #161: イメージに `/etc/tokiwa/tokiwa.yaml`（コメントのみ）が入った。ディレクトリを `/etc/tokiwa/tokiwa.yaml` にマウントしていた構成は
  起動できなくなる（以前は黙って無視されていた設定ミス）。

## 失敗した試み

- `docker run` によるローカル検証（actionlint をコンテナで実行）は実行環境のポリシーで拒否された。自分で起動した dockerd は停止済み。
  以降の Docker 関連の確認は `docker compose ... config`（デーモン不要）とレジストリ参照に限る。
