## 判断したこと（要レビュー）
- 取得失敗時は最後のポリシーを維持（fail-static）。初回取得前は何も強制しない。
- `trust_forwarded_for=false` のときクライアントの X-Forwarded-* は破棄して上書き。`true` は XFF 右端を採用（信頼 LB 1 段想定）。
- 既定で Host を保持して転送（Caddy 流）。`--rewrite-host` で上流ホストに変更可。
- 上流タイムアウトは 504（仕様の「障害時 502」は接続系エラーに適用）。
- `deceive` で一致ルートが無いときの汎用 404 は DECEPTION イベントを出さない（ノイズ回避。HTTP イベントにタグは付く）。
- `*` / `/*` のデコイは拒否（サイト全体を置き換えてしまうため）。
- 注入有効時は Accept-Encoding を gzip/deflate に絞る（br クライアントにも注入するため）。

## 他モジュールへの依頼
- respond: `GET /api/v1/gate/policy` は `GatePolicy` をそのまま返す前提（`version` は内容ハッシュ）。404 の間はゲートは
  ポリシー無しで動作する。
- deception: デコイ本文は `DecoyRoute.body`（UTF-8）、`headers` は hop-by-hop / Content-* / Date / CR・LF を除いて適用。
  ゲートは `kind=deception, dataset=gate.deception, deception.asset_id/asset_kind` を送る。トークンは redact パターンに
  当たらない形式でないと、パス・クエリ・ヘッダ・本文のいずれでもマスクされて検知できない。
- detect-ai: `header_order` は重複を含む到着順（最大 64）。`timestamp` は到着時刻、`duration_ms` は tarpit を含む。
  `labels["gate.action"]` / tags でゲートの判断を参照できる。
- lab-eval: compose では `TOKIWA_GATE__INGEST_TOKEN` か `--token-file`（共有ボリューム）でトークンを渡す。
- 統合担当: 共有ファイルは未編集。docs/architecture.md / api-contract.md への追記は不要な範囲（新 API なし。
  データセット名 `gate.http` / `gate.deception` とタグは docs/gate.md に記載）。
