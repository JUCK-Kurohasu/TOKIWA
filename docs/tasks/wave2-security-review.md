# Wave 2 / F: security-review — 敵対的セキュリティレビュー（フェーズ 2）

## 前提
フェーズ 1 のマージ後。全体を読む権限を持つが、修正は最小限・テスト付き。

## 観点（それぞれ「攻撃者の具体的な経路」を書いてから判定）
1. **LLM 安全**: 攻撃者が制御するテレメトリ（URL、ヘッダ、ボディ、LLM アプリへのプロンプト、CVE 説明文、RSS 本文）が
   トリアージ / 助言 / リサーチ / コパイロットのプロンプトに入る経路。`untrusted_block` の抜け、出力スキーマ外の自由文が
   対処提案・ルール作成・通知に流れる経路、evidence_ids 検証の抜け。対処提案の target 検証（証拠に無い IP、保護 CIDR）。
2. **認証・認可**: ロール境界（viewer/analyst/admin）、API トークンのスコープ、SSE のトークン扱い、ユーザー列挙、
   ブルートフォース対策（ログインのレート制限が無ければ追加を提案）。
3. **SSRF / 外部送信**: webhook・通知・インテル取得・Gate のアップストリーム。DNS リバインディング。
4. **デセプション**: ハニートークンが本物と誤認されない・redact に潰されない・第三者を巻き込まない。
5. **Gate**: リクエストスマグリング（CL/TE）、Host ヘッダ、XFF 信頼、デコイ配信の情報漏えい。
6. **秘密情報**: ログ・DB・監査・LLM 入力への API キーや JWT の混入。
7. 依存関係の既知脆弱性（`uv pip audit` 相当 / `npm audit`）。
